# Contributing to the Twin Ladder Assessment Maturity Model

Thank you for your interest in improving the standard. This document explains how to propose changes.

## Types of contributions

### Pillar indicator feedback
If you believe a maturity indicator is unclear, missing, or incorrectly placed at its current level, open an issue using the "Indicator Feedback" template.

### Level boundary suggestions
If you have evidence that the boundary between maturity levels should be adjusted (e.g., the compliance floor should be 48 instead of 52), open an issue using the "Level Boundary" template with supporting evidence.

### New assessment questions
If you'd like to suggest new assessment questions for the scoring rubric, open an issue using the "Assessment Question" template.

### GDPR/regulatory updates
If new Commission guidance, enforcement decisions, or harmonised standards affect the standard, open an issue with the regulatory reference.

## Process

1. **Open an issue** describing the proposed change with rationale
2. **Community discussion** — 14 days for feedback on the issue
3. **Standard Governance Board review** — quarterly for minor changes, annual for major changes
4. **Public comment period** — 30 days for major changes (structural additions, pillar modifications)
5. **Version release** — changes incorporated into next version

## What we won't change

- The seven-pillar structure (unless overwhelming evidence warrants restructuring — major version change)
- The CC BY-SA 4.0 license
- The competence-specific focus (this is not a governance or risk framework)

## Code of conduct

Be constructive, evidence-based, and respectful. This standard affects how organisations build AI competence — contributions should serve that mission.
